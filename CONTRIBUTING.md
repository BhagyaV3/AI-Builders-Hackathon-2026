# Contributing to AccessBridge

Thank you for contributing to AccessBridge.

## Overview

AccessBridge is a hackathon project focused on turning complex forms into an accessible, guided, and verifiable experience. Contributions should support that goal and stay aligned with the current MVP scope.

## How to Contribute

1. Check the current project plan in [plan.md](./plan.md).
2. Review the issue list in [github-issues.md](./github-issues.md).
3. Pick a task that fits the current MVP.
4. Coordinate with the team before starting work if the task depends on another part of the system.
5. Open a pull request when the work is ready.

## Issue Guidelines

- Use issues for concrete tasks, bugs, and small feature slices.
- Keep titles short and specific.
- Add a short description of the goal and the expected result.
- If the task depends on another issue, mention that in the description.

## Branching

- Create a branch for each task.
- Use a clear branch name tied to the work, for example: `backend-form-extraction` or `frontend-guided-flow`.
- Keep branches focused on one issue when possible.

## Pull Requests

- Keep pull requests small and reviewable.
- Include a short summary of what changed.
- Mention any issue numbers the PR closes or supports.
- Add screenshots or notes if the change affects the UI.

## Code and Review Standards

- Keep the MVP simple.
- Prefer clear code over clever code.
- Preserve accessibility behavior and source fidelity.
- Do not remove deadlines, conditions, or warnings during simplification.
- Test the affected flow before merging.

## Communication

- Ask questions early if a task is blocked.
- Leave comments on issues or PRs when assumptions change.
- Coordinate handoffs between backend, AI, frontend, and QA work.

## Scope Discipline

- Do not expand the project beyond the current MVP without team agreement.
- Optional and stretch ideas should stay optional unless the core flow is already stable.
- If a feature does not help the form caseworker demo, it should probably wait.

## Thank You

Small, focused contributions matter most in a short hackathon timeline.
